# Code vs docs — paths A, B, C, refusals and watch profiles

Walked 2026-10-09: every step of diagrams 02, 03, 04, 09 and 10 against `services/tower-mcp`, `services/alerts`, `services/binding-page`, `packages/tower-policy`, `tower-consent`, `camara-client` and `tower-audit`, plus the Terraform that hosts them. Every file:line was read, not inferred. Nothing is deployed, so AWS behaviour is read from the code and Terraform only.

Deployment-only findings are in [`deployment-agentcore.md`](deployment-agentcore.md) (F1–F13) and are not repeated here. D21 cross-references them.

**25 divergences.** In the **Fix** column, *code* means the doc is right and the code should change, and *doc* means the code is right and the doc should change. Severity: **H** breaks a design rule or a demo claim; **M** is wrong behaviour or a wrong number; **L** is wording or a drawing.

## Top three

1. **D4 (resolved).** If one carrier call failed, the answer could still be "Your line is as it was." A SIM-swap timeout with call forwarding `none` passed the policy as `OK`. Now it is `CARRIER_ERROR` (or `STALE_DATA` from the Watch on a timeout).
2. **D7 (revoke resolved; grant open).** Revoking a grant left the grantee's Watch enabled and the carrier subscriptions on the line live, renewed by the watchdog. Now revoke disables that Watch and the watchdog drops the subscriptions. Granting still creates no Watch.
3. **D9 + D8.** The transplant profile and acknowledged escalation can't be reached from any product path. `watch_line` writes only `self`/`care` with no `requires_ack`. The demo's transplant story calls `watch_line(self)`, so its 20-minute text never fires end to end; only `make showcase-alerts` seeds them. **Specified, not yet implemented:** the line-holder sets the profile and contacts on the binding page ([04 §9](components/04-consent-and-binding.md), [06 §11](components/06-alerts-service.md)).
